# Published-package pilot: codeblast on codeblast

**Date:** 2026-09-24  
**Package:** `codeblast@0.3.2`  
**Repository:** `alloevil/codeblast`  
**Artifact:** [`eval/pilot-2026-09-24.json`](../eval/pilot-2026-09-24.json)

## What was run

A clean temporary checkout installed the published npm package, indexed this repository, and queried
`reviewDecision`:

```bash
npm install --ignore-scripts codeblast@0.3.2
codeblast index . --db /tmp/graph.db
codeblast impact /tmp/graph.db reviewDecision --json
```

## Observed output

| Measure | Result |
|---|---:|
| Files indexed | 32 |
| Nodes | 178 |
| Edges | 921 |
| Repository-wide blind spots | 170 |
| Extraction failures | 0 |
| Impact items for `reviewDecision` | 6 |
| Target-file blind spots | 0 |
| Review-first items | 2 |
| Affected test files | 3 |

The important distinction is between repository-wide blind spots and target-file blind spots. The first
is the expected boundary of static analysis in a real repository; the second determines whether this
particular impact answer may be underestimated.

## What this proves

- The published executable installs and runs outside the source checkout.
- The index completed without extraction failures.
- Machine-readable output separates review-first nodes, tests, conservative items, and warnings.
- The result carries explicit limits instead of presenting all 170 repository-wide blind spots as errors.

## What this does not prove

This is a smoke run and product-adoption case study, not a benchmark. It does not establish universal
recall, precision, or regression-detection accuracy. The bounded mutation-testing evidence is maintained
in [`docs/claims.json`](claims.json) and the committed `eval/mutation-*.json` artifacts.

## Reproduce

Use a clean checkout and run the commands above. For a merge-oriented result over two refs:

```bash
codeblast check-change <repo> <base-sha> <head-sha> --json
```

Treat `safe-to-review` as a routing result, never as proof that a change is safe to merge.
